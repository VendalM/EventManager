# Менеджер событий (EventManager)

Простое и понятное API для управления вашими событиями. Создавайте, редактируйте и удаляйте события с помощью удобных HTTP-запросов.

## Что умеет это API?

### События

*   **Посмотреть все события** — `GET /events`
*   **Найти событие по номеру** — `GET /events/{id}`
*   **Добавить новое событие** — `POST /events` (только `Admin`)
*   **Исправить событие** — `PUT /events/{id}` (только `Admin`)
*   **Удалить событие** — `DELETE /events/{id}` (только `Admin`)

Событие возвращается в следующем формате:

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "title": "Конференция .NET",
  "description": "Ежегодная конференция .NET разработчиков",
  "startDate": "2024-12-15T10:00:00Z",
  "endDate": "2024-12-15T18:00:00Z",
  "totalSeats": 100,
  "availableSeats": 42
}
```

**Как работает:** При создании события указывается общее количество мест (`TotalSeats`). Количество свободных мест (`AvailableSeats`) изначально равно общему количеству мест. При успешном бронировании `AvailableSeats` уменьшается на 1, при отмене бронирования — восстанавливается.

| HTTP статус | Описание |
|-------------|----------|
| 200 OK | Запрос выполнен успешно (GET) |
| 201 Created | Событие успешно создано (POST, PUT) |
| 204 No Content | Событие успешно удалено (DELETE) |
| 400 Bad Request | Ошибка валидации данных |
| 404 Not Found | Событие с указанным ID не найдено |
| 409 Conflict | Недостаточно мест при изменении вместимости события |

### Аутентификация
- `POST /auth/register` — зарегистрировать пользователя. Поле `role` необязательное, по умолчанию используется `User`; для тестирования можно передать `Admin`.
- `POST /auth/login` — выполнить вход и получить пару `accessToken`/`refreshToken`.
- `POST /auth/refresh` — обновить пару токенов по refresh-токену.
- `POST /auth/logout` — отозвать refresh-токен.

JWT настраивается в `Presentation/appsettings.json`: секретный ключ, издатель, аудитория и время жизни access/refresh-токенов. Защищенные запросы выполняются с заголовком `Authorization: Bearer <accessToken>`.

### Бронирования
- `POST /events/{id}/book` — создать бронь для текущего пользователя (статус `Pending`, требуется токен)
- `GET /bookings/{id}` — получить информацию о своей брони; администратор может получить любую бронь
- `DELETE /bookings/{id}` — отменить свою бронь; администратор может отменить любую бронь

**Как работает:** Бронь создаётся со статусом `Pending` и привязывается к пользователю из JWT claims. При создании брони система проверяет, что событие ещё не началось, у пользователя меньше 10 активных броней и есть свободные места (`AvailableSeats`). Если проверки пройдены, количество доступных мест уменьшается на 1, и бронь создаётся. API возвращает `202 Accepted`, тело брони и заголовок `Location: /bookings/{bookingId}`. Затем фоновый сервис обрабатывает бронь и переводит её в финальный статус (`Confirmed` или `Rejected`). При отмене брони статус меняется на `Cancelled`, а место возвращается в событие.

| HTTP статус | Описание |
|-------------|----------|
| 202 Accepted | Бронь принята в обработку |
| 200 OK | Бронь получена по ID |
| 204 No Content | Бронь отменена |
| 400 Bad Request | Событие уже началось |
| 401 Unauthorized | Запрос требует авторизации |
| 403 Forbidden | Нет прав на просмотр или отмену брони |
| 404 Not Found | Событие/бронь с указанным ID не найдено |
| 409 Conflict | Нет свободных мест или превышен лимит активных броней |

### Расширенные возможности

*   **Фильтрация событий** — поиск по названию (регистронезависимый) и диапазону дат
*   **Пагинация** — удобная навигация по большому списку событий
*   **Глобальная обработка ошибок** — единообразные JSON-ответы с информацией о проблеме
*   **JWT-аутентификация и роли** — пользователи с ролями `User` и `Admin`, access/refresh-токены, защищенные эндпоинты
*   **Защита от овербукинга** — предотвращение превышения количества доступных мест при конкурентных запросах
*   **Пользовательские лимиты бронирования** — не больше 10 активных броней на одного пользователя
*   **Потокобезопасное бронирование** — использование `SemaphoreSlim` для синхронизации доступа к критической секции
*   **Фоновая обработка бронирований** — Hosted Service обрабатывает брони со статусом `Pending`

## Как это устроено внутри?

Проект разделён на слои согласно чистой архитектуре:

- **Domain** — ядро бизнес-логики: сущности `Event`, `Booking`, value objects, доменные исключения. Не зависит от других слоёв.
- **Application** — сценарии использования (use cases), DTO, интерфейсы репозиториев (порты), сервисы приложения, исключения прикладного уровня. Зависит только от Domain.
- **Infrastructure** — реализация портов: репозитории на Entity Framework Core, `AppDbContext`, миграции, конфигурации маппинга (AutoMapper). Зависит от Application и Domain.
- **Presentation** — точка входа (веб-проект ASP.NET Core): контроллеры, middleware, Swagger, регистрация зависимостей, фоновый сервис обработки бронирований. Зависит от Application и Infrastructure.

### Обработка ошибок

Middleware глобальной обработки исключений перехватывает все необработанные ошибки и возвращает единообразный JSON-ответ:

| Тип ошибки | HTTP статус | Пример ответа |
|------------|-------------|---------------|
| Ошибка валидации | 400 Bad Request | `{"status": 400, "detail": "Не заполнен заголовок события"}` |
| Ресурс не найден | 404 Not Found | `{"status": 404, "detail": "Сущность с идентификатором '3fa85f64-5717-4562-b3fc-2c963f66afa6' не найдена."}` |
| Нет свободных мест | 409 Conflict | `{"status": 409, "detail": "Для события 'Конференция .NET' нет свободных мест."}` |
| Событие уже началось | 400 Bad Request | `{"status": 400, "detail": "Нельзя забронировать прошедшее событие 'Конференция .NET'."}` |
| Превышен лимит активных броней | 409 Conflict | `{"status": 409, "detail": "Превышен лимит активных броней. Максимум: 10."}` |
| Нет прав на операцию | 403 Forbidden | `{"status": 403, "detail": "Недостаточно прав для выполнения операции."}` |
| Внутренняя ошибка | 500 Internal Server Error | `{"status": 500, "detail": "..."}` |

### Фильтрация событий

Метод `GET /events` поддерживает следующие параметры:

| Параметр | Тип | Описание | Пример |
|----------|-----|----------|--------|
| `title` | string | Поиск по названию (регистронезависимый, частичное совпадение) | `?title=конференция` |
| `from` | DateTime | События, начинающиеся не раньше указанной даты | `?from=2024-12-01` |
| `to` | DateTime | События, заканчивающиеся не позже указанной даты | `?to=2024-12-31` |
| `page` | int | Номер страницы (по умолчанию 1) | `?page=2` |
| `pageSize` | int | Количество элементов на странице (по умолчанию 10) | `?pageSize=20` |

**Пример запроса с фильтрацией и пагинацией:**

`GET /events?title=конференция&from=2024-12-01&to=2024-12-31&page=2&pageSize=10`

### Интеграционные тесты

Для проверки реальной работы с PostgreSQL используются интеграционные тесты на основе **Testcontainers**.  
Они запускают изолированный контейнер PostgreSQL в Docker, выполняют тесты и автоматически его останавливают.

**Требования:**  
- Установленный и запущенный Docker  
- Доступ к интернету для скачивания образа `postgres:16-alpine`

**Запуск интеграционных тестов:**

```bash
dotnet test tests/EventApi.IntegrationTests
```

## Запуск

Для API используется PostgreSQL. По умолчанию строка подключения берётся из `src/Presentation/appsettings.json` (`ConnectionStrings:Default`).

```bash
dotnet restore
dotnet run --project src/Presentation/Presentation.csproj
```

Swagger доступен в Development-среде (по профилю запуска: `https://localhost:7013/swagger` или `http://localhost:5068/swagger`).
